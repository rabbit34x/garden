# Discordスレッド運用ルール

2026-10-10（JST）、ユーザーとのDiscordスレッドで合意。

## タイトル

- 形式は `MMDD 概要`。
- MMDDはスレッド作成日の日本標準時（JST／UTC+9）。月・日ともに2桁。
- 概要は話題や目的が分かる短い日本語。
- 途中でタイトルを変更する場合も、日付は作成日のままとする。
- 終了時にタイトルを変更する必要はない。「完了」などの印も追加しない。

## 終わり方

- Luluが話題・作業の一区切りと判断したらサマリーを作成し、Obsidianの `lulu/` 内にまとめる。
- サマリーには結論・決定事項、実施したこと、残った課題を必要に応じて記載する。
- 実際に実施したことと提案・未実施事項を区別する。
- 既存のノートテンプレートを利用し、公開は無効のままにする。

## まとめの保存先と構成

2026-10-10（JST）、ユーザーの保存先も設計しておくべきとの指摘を受け、Luluが以下の配置・命名方針を整備した。

- 標準の保存先は `lulu/スレッドまとめ/`。
- ファイル名は `YYYY-MM-DD 概要.md`。日付は元スレッド作成日のJSTとし、更新時も変更しない。同日同名の別スレッドはスレッドIDを追加して区別する。
- 本文に元スレッドIDと記録日・更新日（JST）を残す。作成前にスレッドIDで既存記録を確認し、再開時は同じ記録を更新する。
- 基本構成は「目的」「結論・決定事項」「実施・検証」「残った課題・次の行動」「関連ノート・出典」。不要な項目は省略し、未実施を完了と書かない。次の行動も、合意や実行開始を捏造しない。
- `スレッドまとめ/` は会話の結論と経緯、`作業記録/` は詳細な手順・実測、`運用ルール/` は今後も適用する取り決めを扱う。詳細はリンクで参照し、本文を重複させない。
- スレッドのまとめは `lulu/スレッドまとめ/` に保存する。既存の作業記録や運用ルールはまとめの代替にせず、まとめ側に短い結論と関連ノートへのリンクを残す。同じスレッドのまとめは一つに保ち、再開時もそれを更新する。
- `lulu/ノート案内.md` はMOC専用とし、分類別のリンクと短い説明だけを置く。作業ログ、終了サマリー、運用ルール本文を置かない。`lulu/README.md` はLuluの自己紹介ページとして扱う。
- `lulu/` 内の移動はユーザーが許可している。公開設定が有効であることだけを理由に移動を控えず、移動前に参照元・定期実行の参照を確認し、変更可能な参照を更新する。ユーザーの既存ノートやVault設定は編集しない。内容と証拠は保持し、公開済みURLの継続性を未検証のまま保証しない。
